# CCUT MASTER CONCEPT 1.0

> 발행: 국장 (2026-07-12) — **모든 코딩 에이전트와 작업자가 먼저 읽어야 하는 CCUT 최상위 개념서.**
> 기능 지시서·계약 문서와 충돌하는 것처럼 보이면, 이 문서의 세계관이 해석 기준이다
> (단 EDIT-CONTRACT-B0 등 확정 계약의 수정 자체는 국장 게이트 G3).

기획하고 촬영하면, 나머지는 CCUT 방송국이 완성한다

## 1. CCUT의 한 문장 정의

CCUT은 AI 기능이 붙은 영상 편집기가 아니다. 사용자가 기획하고 영상을 촬영하면, 영상 정리·조각화·스토리 구성·편집·음향·자막·검수·출력을 방송국 제작진처럼 수행하는 로컬 AI 제작실이다.

사용자는 편집 기술을 배울 필요가 없다. 사용자가 해야 할 일은 세 가지다.

1. 무엇을 만들지 생각한다.
2. 영상을 촬영한다.
3. CCUT과 결과를 보며 이야기한다.

프레임을 일일이 자르고, 타임라인을 확대하고, 수백 개의 조각을 옮기고, 어려운 전환 효과와 음향 기술을 익히는 일은 CCUT의 일이다.

## 2. CCUT이 사용자에게 약속하는 것

사용자는 이렇게 느껴야 한다: "내가 편집 프로그램을 사용하는 것이 아니라, 내 영상을 잘 아는 제작진과 같이 일하고 있다."

사용자는 이런 말을 자유롭게 할 수 있어야 한다.
- "오늘 여행에서 가족끼리 웃었던 장면 중심으로 만들어줘."
- "물놀이 장면은 너무 많으니 줄여줘." / "이 대화는 반복되니까 빼자."
- "아이 표정이 좋은 부분은 조금 더 길게 보여줘." / "여기서 갑자기 넘어가니까 어색해."
- "앞부분은 재미있는데 뒤가 늘어져." / "유튜브용으로 8분 정도면 좋겠어."
- "이 내용은 처음에 나오면 안 되고 뒤에서 밝혀졌으면 좋겠어."
- "내가 말한 건 장면 전체 삭제가 아니라 가운데 말만 빼는 거야."
- "조금 더 따뜻하고 가족적인 느낌으로 해줘."

사용자는 CCUT의 내부 기능 이름(EXCLUDE_RANGE, TRIM, MOVE, J-CUT, L-CUT, LOUDNESS, CONTINUITY …)을 몰라도 된다.
편집 계약은 사용자의 표현을 제한하는 규칙이 아니라, **AI가 안전하고 정확하게 실행하도록 제한하는 내부 규칙**이다.

## 3. CCUT의 제품 형태

프리미어·다빈치·캡컷의 축소 복제가 아니다. 복잡한 타임라인과 수십 개의 도구 버튼이 중심이 되어서는 안 된다.
중심 화면은 세 가지면 충분하다.

### ① 원고
영상 전체가 연속된 글로 보인다 — 영상 속 말, 장면 설명, 사람과 행동, 중요한 순간, 촬영 시간과 원본 위치.
카드 수백 개를 나열하지 않는다. 워드 문서를 읽듯이 전체 내용을 읽고, 문장을 클릭하면 해당 영상이 재생된다.

### ② 이야기
사용자가 만들고 있는 최종 영상의 이야기 — 순서 변경, 삭제, 추가 요청, 강조, 길이 조정, 설명·내레이션, 사용자 의견.
이야기를 텍스트로 다듬으면 영상 편집이 따라온다.

### ③ 결과
CCUT이 만든 편집본을 본다. 사용자는 결과를 보면서 말한다 — "여기는 좋다." "이 장면은 너무 길다." "이 다음이 어색하다."
CCUT은 그 말을 영상의 정확한 위치와 연결해 다시 편집한다.

## 4. CCUT 방송국의 직원들

수많은 AI 프로세스를 동시에 실행하지 않는다. **하나의 지휘자와 여러 개의 역할** — 하나의 로컬 AI가 상황에 따라 역할을 바꾸며 일한다.

- **자료 정리 직원**: 파일 확인·촬영 순서·음성 전사·장면 변화·사람/행동/장소 기록·중복/무음/흔들림/실수 후보 표시
- **조각 편집 직원**: 말과 행동이 끝나는 지점에서 조각 생성·긴 조각 세분화·짧은 조각 병합·대화/행동/반응 구분·중요 구간 세밀 분석
- **스토리 작가**: 의도 파악·관련 장면 검색·시작/전개/전환/마무리 구성·부족/중복 장면 발견·두세 가지 방향 제안
- **영상 편집자**: 조각 선택·순서·중복 대화 제거·말 안 끊기게 경계 조정·반응/보조 화면 삽입·호흡과 속도·반복 제거
- **음향 편집자**: 소리 크기 정리·급격한 음량 변화 방지·말/배경음 균형·전환 시 소리 끊김 완화·잡음/무음 처리
- **자막 담당자**: 음성 기반 자막·오인식 경고·읽기 좋은 분리·고유명사 사용자 수정 반영
- **검수 직원**: 검은 화면·잘린 말·중복·과단축 장면·음량 이상·화면비·원본 없는 주장·제외 요청 위반 최종 확인
- **배포 담당자**: 유튜브/쇼츠/인스타 출력·썸네일 후보·제목/설명 초안·챕터/자막 파일·업로드 전 확인

## 5. CCUT의 전체 흐름

```
영상 투입 → 가벼운 전체 조사 → Evidence Ledger 생성 → 조각 후보 생성
→ 사용자와 이야기 구성 → Story Timeline 확정 → 자동 편집
→ 음향·자막·전환·화면 정리 → 미리보기 → 사용자 대화 수정 → 최종 출력
```

이 모든 과정이 하나의 프로젝트 안에서 이어진다. 각 단계가 서로 다른 데이터를 마음대로 만들면 안 된다.

## 6. 핵심 개념 (코드가 반드시 구분해야 할 층)

| 개념 | 정의 | 핵심 필드 |
|---|---|---|
| **Source Asset** | 원본 영상 — 변경하지 않는다 | source_id, file_path, duration, fps, … |
| **Evidence Span** | 원본의 특정 시간 범위에서 관찰된 사실 — 스토리가 바뀌어도 불변 | source_id, start_ms, end_ms, transcript, visual_description, people, actions, audio_state, confidence |
| **Ledger Span** | Evidence를 사용자가 읽는 원고 항목으로 만든 것 — 원본에 붙어 있고, 아직 사용본 아님 | ledger_span_id, source_id, anchor_start_ms, anchor_end_ms, text, visual_note |
| **Fragment** | 편집 후보 조각 — 고정 돌덩이 아님(세분/병합/경계 조정 가능), 단 원본 좌표 유지 | |
| **Timeline Item** | 이야기 속 실제 사용본 — 같은 장면 두 번 쓰면 두 개, 각자 다른 편집 상태 가능 | timeline_item_id, ledger_span_id/anchor, story_order, purpose |
| **Story Document** | 사용자가 읽는 최종 이야기(도입·전개·전환·반응·결말) — 자유 수정, 새 문장 입력 허용 | |
| **Edit Intent** | 사용자의 자유로운 말 | |
| **Edit Plan** | CCUT이 이해한 작업 — 대상·이유·예상 결과·명령·불확실성. 사용자에게는 자연어로 | |
| **Edit State** | 승인된 편집만 저장 — trim·중간 제외·조각 제외·복원 | |
| **Render Span** | Edit State를 계산한 최종 재생 구간 — **저장된 진실이 아니라 계산 결과**. Preview/Export는 이것만 소비 | source_id, start_ms, end_ms, timeline_order |
| **Receipt** | 무엇이 왜 바뀌었는지 — 요청·해석·변경·전후·승인/취소. 취향 학습의 재료 | |

Story Document에 영상에 없는 문장이 와도 오류로 삭제하지 않는다 — "해당 장면을 찾지 못했습니다. 웃는 장면을 대신 쓸까요, 자막·내레이션으로 표현할까요?"처럼 해결책을 제안한다.

## 7. 대량 영상의 단계적 분석

1차 아주 가벼운 전체 조사(길이·상태·음성·음량·장면 변화·흔들림·무음·대표 프레임·ASR) → 2차 거친 조각 생성(문장 경계·침묵·전환·행동 변화·촬영 중단·반복) → 3차 **필요한 구간만** 시각 분석(반응·이야기 관련·경계 불확실·후보 선택·최종 포함 가능성) → 4차 사용자 의도 기반 재조사(Evidence Ledger에서 먼저 찾고 필요한 부분만 추가 분석) → 5차 선택된 구간만 정밀 편집(경계·표정 종료·오디오 연결·자막 타이밍·전환).

**전체는 가볍게 보고, 필요한 곳만 깊게 본다.**

## 8. 대화 방식

사용자 표현을 내부 분류(검색/스토리/편집/스타일/질문/검수/출력)하되 사용자에게 분류를 보이지 않는다.
- 명확한 요청("이 문장만 빼줘") → 단어 시간좌표 → 삭제 미리보기
- 애매한 요청("여기 좀 어색해") → 앞뒤 장면 진단(잘린 말·검은 프레임·음량 급변·과단축·흐름) → 한두 개 해결안 제시
- 영상에 없는 요청 → ①실제 검색 ②유사 장면 ③자막/내레이션/음향 대안 ④사용자 선택. **불가능하다는 말로 대화를 끝내지 않는다.**

실행 흐름: 자유 표현 → 문맥 해석 → 근거·위치 확인 → Edit Plan → 미리보기 → 승인 → 실행.
단, 명백하고 쉽게 되돌릴 수 있는 작업은 설정에 따라 즉시 실행 가능.

## 9. 스토리 구성

CCUT이 먼저 혼자 결정하지 않는다. 큰 흐름·인물·반복·사건·반응·공백·분량을 먼저 보여주고, 두세 방향을 제안하고, 사용자와 기준을 잡은 뒤 Story Document를 만든다. 사용자는 읽고 옮기고 지우고 다시 말한다.

## 10. 편집의 전문성 = 판단

어디서 시작/끝낼지, 어떤 반응을 보여줄지, 무엇을 생략할지, 어떤 순서가 자연스러운지, 언제 숨 쉬게 할지, 소리를 어떻게 이을지.

기본 원칙: 말이 중간에 잘리지 않는다 / 의미 없는 침묵은 줄인다 / 중요한 표정은 급히 자르지 않는다 / 같은 말 반복 금지 / 전환에는 이유 / 기본은 하드컷 / 전환 효과로 문제를 숨기지 않는다 / **오디오가 영상보다 먼저 안정** / 화면보다 이야기 우선.

자동 기술: 문장 단위 컷·중간 발언 제거·점프컷 완화·반응 삽입·B-roll·J/L-cut·음량 정규화·오디오 연결·자막 생성/줄 나누기·화면비·인물 크롭·검은 화면 제거·과단축 경고·중복 발견·엔딩 여백. 사용자는 직접 조작하지 않는다.

## 11. PBE의 새로운 역할

PBE는 중심 편집기가 아니다. AI가 대부분 편집한 뒤 **예외를 확인하는 정밀 감독창**이다 (정확한 한 부분 확인·컷 위치 미세 수정·중간 장면 하나 제외·AI가 놓친 예외).
사용자가 영상 전체를 PBE에서 프레임 단위로 작업해야 한다면 CCUT의 목표가 실패한 것이다.

## 12. 로컬 AI 구조

핵심 작업은 인터넷 없이 완료된다.
- 로컬 모델: 말 해석·문맥 이해·Evidence 검색·스토리 후보·Edit Plan·설명/확인·취향 학습
- 일반 코드: 시간좌표 계산·분할·DB·파일·Preview·Export·음량·자막 타이밍·계약 검증
- **AI가 직접 영상 파일과 DB를 수정하지 않는다**: Local AI Director → 구조화된 계획 → 결정론적 편집 엔진 → Preview/Export
- API AI는 선택형 고급 기능일 뿐, 생존 조건이 아니다.

## 13. 프로젝트 문맥 기억

프로젝트 목표(목적·시청자·길이·플랫폼·분위기·필수/제외) + 사용자 선택(스토리·삭제/복원·유지·거부·속도 선호) + 현재 문맥(선택 조각·재생 위치·가리킨 문장·앞뒤·직전 수정)을 기억해야 "여기", "아까 것", "그 사람", "다음 장면"을 이해한다.

## 14. 가볍고 빠른 시스템 실행 원칙

- **CCUT Job Conductor 하나**가 모든 분석 작업 관리 (job_id, project_id, stage, pid, resource, started_at, heartbeat, progress, cancel_requested)
- 무거운 GPU 작업(ASR·VL·렌더)은 큐로 한 번에 하나. CPU도 제한된 worker.
- **숨은 작업 금지** — 모든 작업은 화면에 표시(무엇·어느 영상·진행률·중지·재개·실패 이유)
- **좀비 방지** — 종료/재시작 시 PID 확인·heartbeat 없는 작업 정리·임시 파일·DB lock 해제·중단 지점 재개
- **worktree writer lock — 같은 worktree에 writer 1명만.** 동시 수정 감지 시 즉시 한쪽 정지.
- **재분석 최소화** — (source hash, analysis/model/settings version) 키 캐시. 스토리 변경이 ASR/전체 VL 재분석을 유발하지 않는다.

## 15. 만들지 말아야 할 것

프리미어 복제품 / 수백 버튼 전문 UI / 전 프레임 VL 분석 / 상시 다중 에이전트 병렬 / 데이터 중복 저장 / 명령어 문법을 공부해야 하는 자연어 / 조각 ID 암기 UI / 효과 남용 = 전문성 착각 / API 없으면 죽는 제품 / 최종적으로 프레임 노가다를 시키는 제품.

## 16. 개발 순서 (수직 흐름 우선)

1. **작업 지휘와 데이터 개념 통일** — Source/Evidence/Ledger Span/Timeline Item/Edit State/Render Span/Receipt를 코드 전체에서 같은 의미로. Job Conductor + worktree writer lock.
2. **하루치 영상 원고화** — 가벼운 분석·ASR·장면 변화·조각 후보·연속 원고. 원고를 읽고 클릭 재생.
3. **사용자와 스토리 구성** — 요약·사건/인물·방향 제안·자유 대화·Story Document 생성·텍스트 이동/삭제/추가.
4. **Story Document에서 자동 편집** — 삭제·이동·중간 문장 제거·경계 조정·복원이 Preview에 반영.
5. **방송 편집** — 호흡·반응·B-roll·오디오 연결·자막·화면비·음량·전환 자동 처리.
6. **대화 수정과 학습** — 결과를 보며 말하면 수정하고 차이를 Receipt로 남긴다.

## 17. 첫 번째 완성 목표

사용자가 하루 동안 촬영한 여러 영상을 넣는다. CCUT이 전체 내용을 원고로 정리한다. 사용자는 원하는 방향을 평소 말로 설명한다. CCUT이 이야기를 구성하고 편집본을 만든다. 사용자는 결과를 보며 몇 번 대화한다. **프레임 편집을 거의 하지 않고 유튜브에 올릴 영상을 얻는다.** 이 흐름 완성 전에는 고급 효과가 우선이 아니다.

## 18. 모든 작업자에게 주는 최상위 지시

```
CCUT은 AI 영상 편집 도구가 아니다.
사용자가 기획하고 촬영하면 나머지를 수행하는 로컬 AI 제작실이다.

사용자는 편집 명령어와 전문 기술을 몰라도 된다.
사용자는 자유롭게 말하고, 원고를 읽고, 결과를 보며 의견을 준다.

CCUT은 전체 영상을 가볍게 조사하고, 필요한 구간만 깊게 분석한다.

Evidence는 원본 사실, Ledger는 읽을 수 있는 원고,
Timeline Item은 이야기 속 사용본, Edit State는 승인된 편집,
Render Span은 계산된 출력이다. 각 층의 진실은 하나만 둔다.

스토리는 사용자와 함께 구성한다.
AI가 독단적으로 최종 이야기를 결정하지 않는다.

편집의 전문성은 효과의 수가 아니라
좋은 시작점·끝점·순서·반응·호흡·소리의 판단이다.

PBE는 전체 편집기가 아니라 예외를 감독하는 최종 정밀창이다.

모든 핵심 기능은 로컬에서 작동해야 한다.
API는 선택형 보조 수단일 뿐 필수 조건이 아니다.

여러 에이전트와 프로세스가 제멋대로 움직이지 않는다.
하나의 Job Conductor가 작업·자원·중지·재개를 통제한다.
같은 worktree에는 한 명의 writer만 존재한다.

최종 목표는 사용자가 프레임을 자르고 붙이는 노동에서 벗어나,
기획하고 촬영하고 CCUT과 이야기하는 것만으로
유튜브 영상을 완성하게 하는 것이다.
```

## 이번 방향의 핵심

B0 편집 계약, Text Ledger, Story Timeline은 목적 자체가 아니다. 전부 이 한 문장을 실현하기 위한 내부 부품이다:

**"사용자는 영상을 찍고 CCUT에게 이야기한다. CCUT은 방송국 제작진처럼 이해하고, 구성하고, 편집하고, 완성한다."**

사용자의 자유를 줄여서 정확성을 만드는 것이 아니라, CCUT이 영상·원고·현재 화면·이전 대화를 충분히 이해하게 만들어 사용자가 제약을 의식하지 않도록 하는 것이 중심이다.
