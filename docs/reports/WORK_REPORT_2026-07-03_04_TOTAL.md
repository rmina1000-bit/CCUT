## 한 장 요약 (일반인 언어)

이틀 동안 CCUT은 다음 네 가지가 달라졌습니다.

1. **말이 끝까지 통한다** — "해변만", "은한이 나오는 장면만" 같은 말이 입구에서
   버려지지 않고, 판단을 거쳐, 화면의 A/B 영상과 조각맵까지 정확히 도달한다.
   (이 완주가 처음으로 raw 검증됨)
2. **화면이 흐른다** — 중앙창이 고정 패널에서 대화형 타임라인으로 바뀌었다.
   개략·채팅·지난 제안이 위로 흘러가고, 새 제안은 방금 말한 자리 아래에 선다.
   옛 제안은 "다시 열기"로 복원되고 조각맵이 따라온다.
3. **사람을 알아본다** — 영상 속 얼굴을 자동으로 모아 "이 사람 누구예요?"라고 묻고,
   이름을 저장하면 그 즉시 "OO 나오는 장면만"이라는 명령이 통한다. (은한이·엄마 저장 완료)
4. **두 번 일하지 않는다** — 한 번 판단한 조각은 기억한다. 같은 질문은 0초,
   영상을 추가하면 새 조각만 판단(319조각 610초 → 재질문 0초 / +5조각 10초).
   편집이 도는 동안 화면이 멈추던 문제도 해소(응답 3~4ms).

## 2. 센서층 대수술 (근본 결함 2건)

- **AUTO-REINDEX 잠금 즉사**: SQLite 잠금으로 재인덱스가 조용히 연쇄 실패
  → 16개 중 12개 프로젝트가 센서 장님 → 무엇을 물어도 keep 과소/0 (honest-empty 빈발의 뿌리).
  수리: busy_timeout 30s + 전 프로젝트 상환(tools/reindex_blind.py, 22소스 재인덱싱).
  실증: Camellia "실내" keep 0/46 → 20/46.
- **인덱서 장기 트랜잭션이 제안 저장을 굶김**: purge~commit 사이 수 분 write lock
  → `PROJECT PROPOSAL ERROR: database is locked` (응답은 200인데 빈손, 프론트는 침묵).
  수리: 조각 단위 commit + SQLAlchemy busy 30s + 프론트 실패 사유 대화 환류. 이후 locked 0건.
