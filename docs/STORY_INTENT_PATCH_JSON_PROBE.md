# StoryIntentPatch JSON Probe Specification

## 1. Objective
Define the validation criteria for JSON responses generated by local LLM providers within the AI Boundary.

## 2. Mandatory Contract Keys
Every successful `StoryIntentPatch` must contain:
- `patch_type`: Always `"story_intent_patch"`.
- `tone`: (e.g., `"fast"`, `"emotional"`, `"cinematic"`).
- `target_length`: (e.g., `"short"`, `"medium"`, `"long"`).
- `must_keep`: List of fragment IDs or descriptions (can be empty).
- `avoid`: List of fragment IDs or descriptions (can be empty).
- `reason`: A short string explaining the model's reasoning.

## 3. Probe Strategy
Use `tools/probe_ollama_timeout_stabilization.py` to:
1. Send a short, structured prompt.
2. Force `format: json`.
3. Measure the time to first byte and total generation time.
4. Validate the presence of all 6 mandatory keys.

## 4. Findings (R10-D Smoke-Test)
- **Model**: `qwen3:0.6b`
- **Result**: Initial tests confirmed that 10s is insufficient for first-time loading on dev hardware. 
- **Refinement**: 30s is the new stabilization baseline for R10-E (4B validation).

## 5. Security Note
Local models must not be prompted to generate executable code or access the file system. The prompt must remain strictly bounded to narrative intent analysis.
